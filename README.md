# Family Tasks

PWA для семейных задач: React + Vite (`web/`), Node + Fastify (`server/`), PostgreSQL. Всё упаковано в Docker.

## Запуск в Docker на своём компьютере

Это проверка «как в проде», но без HTTPS и доменов. Развёртывание на сервере описано ниже, в разделе «Деплой на сервер».

```bash
cp .env.example .env   # поменяйте пароль
docker compose up --build
```

Приложение: http://localhost:8080. Nginx отдаёт фронтенд и проксирует `/api` на сервер.

Письма с кодами входа в dev уходят в Mailpit (профиль `dev-mail` из `.env.example`), читать их можно на http://localhost:8025. В проде уберите `COMPOSE_PROFILES` и задайте `SMTP_*` в `.env`.

## Локальная разработка

Одна команда поднимает всё, фронтенд обновляется в браузере при каждом сохранении файла (HMR), сервер перезапускается сам:

```bash
npm run setup   # один раз: зависимости корня, server/ и web/
npm run dev
```

Команда запускает в Docker только БД и Mailpit, затем сервер (http://localhost:3000) и Vite. Адрес приложения напечатает Vite (обычно http://localhost:5173), `/api` проксируется на сервер, письма с кодами видны на http://localhost:8025. Если `.env` нет, он создаётся из `.env.example`. Остановка: Ctrl+C, а БД и Mailpit выключает `npm run dev:stop`.

Service worker в dev выключен, PWA проверяйте на сборке (`docker compose up --build` или `npm run build && npm run preview` в `web/`). Если в браузере остался service worker от старых запусков, удалите его в DevTools → Application → Service Workers.

## Миграции БД

SQL-файлы лежат в `server/migrations/` (формат `-- Up Migration` / `-- Down Migration`), используется [node-pg-migrate](https://github.com/salsita/node-pg-migrate). Сервер применяет новые миграции сам при старте. Вручную (нужен `DATABASE_URL` из `.env`):

```bash
cd server
npm run migrate:create -- add-tasks   # новый файл миграции
npm run migrate:up
npm run migrate:down                  # откат последней
```

## Как устроен вход

- Регистрация и вход идут через email и одноразовый код из письма (6 цифр, 10 минут, 5 попыток, повторная отправка не чаще раза в минуту).
- Создатель семьи (мама/папа) указывает роль, имя и email, подтверждает email кодом и получает код семьи и первое приглашение на 7 дней.
- Присоединяются по ссылке `/join?code=...` (мама/папа/ребёнок) с тем же подтверждением email. Имя и email в семье уникальны, один email может состоять в нескольких семьях (ребёнок может указать почту родителя).
- Вход на другом устройстве: `/login`, email и код. Если email есть в нескольких семьях, предлагается выбрать. У каждого устройства своя сессия, «Выйти» отзывает только её.
- Владелец на странице семьи видит действующее приглашение и может выпустить новое (старое сразу перестаёт работать).
- Если на устройстве уже есть вход, перед заменой показывается подтверждение.
- На устройстве в IndexedDB хранятся код семьи, роль, имя и токен сессии. В БД лежит только SHA-256 хэш токена; токен отправляется как `Authorization: Bearer`.
- Сервер отвечает одинаково на запрос кода для известного и неизвестного email, чтобы адреса нельзя было перебирать.

### Ограничения запросов

Общий лимит 120 запросов в минуту с одного IP, для отправки кодов, создания семьи, входа и приглашений — 10 в минуту. Сервер доверяет заголовку `X-Forwarded-For`, поэтому он должен быть доступен только через nginx.

## Push-уведомления

Приложение шлёт Web Push: о дне рождения участника семьи (в 10:00), об уроках на следующий учебный день (в 17:00, только детям) и о тренировке за 2 часа до начала (только детям, у тренировки должно быть указано время начала). Время считается по часовому поясу устройства, на которое включены уведомления.

- **Ключи VAPID.** Создайте один раз и положите в `.env` (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT=mailto:ваш@адрес`):

  ```bash
  cd server && npm run vapid
  ```

  Менять ключи после запуска нельзя: все подписки перестанут работать. Без ключей уведомления выключены, сервер предупредит об этом при старте.
- **Включение.** «Настройки» → «Уведомления» → «Включить уведомления» (браузер спросит разрешение), там же кнопка «Проверить уведомление». Работает в собранной версии (`docker compose up --build`): в режиме `npm run dev` service worker выключен.
- **Условия.** Нужен HTTPS (на `localhost` не нужен). На iPhone и iPad уведомления есть только у приложения, добавленного на экран «Домой» (iOS 16.4+).

### Как проверить, не дожидаясь 10:00 и 17:00

1. Запустите собранную версию и откройте её в обычном Chrome: `docker compose up --build -d`, затем http://localhost:8080. Войдите, в «Настройках» включите уведомления и нажмите «Проверить уведомление».
2. Для плановых уведомлений поднимите БД с открытым портом и запустите проход планировщика с нужным временем (по вашему часовому поясу):

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d db
   cd server
   npm run notify:tick -- 10:05 --reset   # дни рождения (окно 10:00–12:00)
   npm run notify:tick -- 17:05 --reset   # уроки ребёнку на следующий учебный день (окно 17:00–19:00)
   npm run notify:tick -- 16:05 --reset   # тренировка в 18:00 (напоминание в 16:00–16:15)
   ```

   Для дня рождения в профиле должна быть указана сегодняшняя дата (год любой, в прошлом), для уроков нужен ребёнок с расписанием на следующий учебный день. `--reset` очищает журнал, иначе повторный запуск ничего не отправит.

## Деплой на сервер (DigitalOcean и др.) с HTTPS

Схема: Caddy принимает HTTPS (сам получает и продлевает сертификат Let's Encrypt) → nginx с фронтендом → Node → Postgres. Всё запускается в Docker одной командой. Нужно: сервер с Ubuntu (хватит самого маленького дроплета), **домен** и **почтовый сервис** для писем с кодами входа.

### Что подготовить заранее

1. **Домен.** В DNS добавьте A-запись домена (например, `family.example.com`) на IP сервера. Сертификат выдаётся на домен, на голый IP нормальный не получить. Для быстрой пробы без покупки домена подойдёт `ваш-ip-через-дефисы.sslip.io` (для 203.0.113.10 это `203-0-113-10.sslip.io`). Проверка, что запись заработала: `getent hosts family.example.com` должен показать IP сервера (изменения DNS доходят от нескольких минут до часа).
2. **Почтовый сервис.** Вход и регистрация только по коду из письма, без рабочей почты никто не войдёт. Нужны данные SMTP: хост, порт, логин, пароль и адрес отправителя. DigitalOcean может блокировать исходящий SMTP на портах 25, 465 и 587, поэтому берите сервис, у которого есть порт 2525 (Mailgun, Postmark, Brevo, SendGrid и др.).
3. **Доступ к репозиторию** с сервера: если репозиторий приватный, добавьте на сервере ключ доступа (deploy key) или используйте токен.

### Первый запуск, по шагам

Подключитесь к серверу: `ssh root@IP-СЕРВЕРА`.

```bash
# 1. Docker (в комплекте идёт Compose, нужна версия 2.24 или новее)
curl -fsSL https://get.docker.com | sh
docker compose version

# 2. Брандмауэр: открыты только SSH, HTTP и HTTPS
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 443/udp
ufw --force enable

# 3. Код
git clone АДРЕС-РЕПОЗИТОРИЯ family-tasks
cd family-tasks

# 4. Настройки
cp .env.example .env
nano .env
```

В `.env` заполните (остальное оставьте как есть):

```bash
COMPOSE_FILE=docker-compose.yml:docker-compose.prod.yml   # продакшен-режим с Caddy: после этого команды ниже короткие
COMPOSE_PROFILES=                                         # пусто: Mailpit (локальная почта) в продакшене не нужен
DOMAIN=family.example.com

POSTGRES_PASSWORD=...        # длинный пароль; без знаков / + = @ : (они ломают подключение), лучше hex: openssl rand -hex 24

SMTP_HOST=smtp.example.com
SMTP_PORT=2525
SMTP_USER=...
SMTP_PASS=...
SMTP_FROM="Семейные задачи <noreply@family.example.com>"

VAPID_PUBLIC_KEY=...         # ключи для push-уведомлений, создайте командой ниже и больше не меняйте
VAPID_PRIVATE_KEY=...
VAPID_SUBJECT=mailto:вы@example.com   # ваш настоящий адрес
```

Ключи VAPID (один раз, значения скопируйте в `.env`):

```bash
docker run --rm node:22-alpine npx --yes web-push generate-vapid-keys
```

Запуск:

```bash
docker compose up -d --build
docker compose ps                  # все сервисы должны быть Up
docker compose logs -f caddy       # видно, как выпускается сертификат (Ctrl+C, чтобы выйти)
```

Через минуту приложение открывается по `https://ВАШ-ДОМЕН`. Проверьте вход: введите email, письмо с кодом должно прийти. Миграции БД применяются сами при старте сервера.

### Обновление

```bash
cd family-tasks
git pull
docker compose up -d --build
```

Пересобираются только изменившиеся образы, данные не затрагиваются.

### Повседневные команды

```bash
docker compose ps                         # состояние
docker compose logs -f server             # логи приложения (ошибки отправки писем и уведомлений тут)
docker compose logs -f caddy              # логи HTTPS и сертификатов
docker compose restart server             # перезапустить один сервис
docker compose down                       # остановить всё (данные сохраняются)
docker compose up -d                      # запустить снова
```

**Не используйте `docker compose down -v`**: флаг `-v` удаляет тома, то есть всю базу (`pgdata`) и сертификаты (`caddy_data`).

### Резервная копия и восстановление БД

```bash
# копия (положите файл в надёжное место вне сервера, например скачайте через scp)
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup-$(date +%F).sql

# восстановление в пустую базу
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < backup-2026-10-10.sql
```

### Если что-то не работает

- **Нет сертификата, браузер ругается.** `docker compose logs caddy`. Чаще всего домен ещё не указывает на сервер (`getent hosts ДОМЕН` должен показать IP сервера) или закрыт порт 80 или 443. Исправьте и перезапустите: `docker compose restart caddy`.
- **Письма с кодом не приходят.** `docker compose logs server | grep -i "email"`: там будет причина (неверный пароль SMTP, заблокированный порт). Проверьте `SMTP_*` в `.env`, после правки `docker compose up -d`.
- **Не работают уведомления.** Нужен HTTPS, заполненные `VAPID_*` и включение в «Настройки» → «Уведомления». На iPhone приложение должно быть добавлено на экран «Домой». Подробнее в разделе про push выше.
- **Сервер не стартует после смены пароля БД.** Пароль применяется только при создании базы. Для уже созданной БД смените его в самом Postgres или (если данных нет) пересоздайте том.

Лимиты запросов считаются по IP посетителя: nginx берёт его из заголовка `X-Forwarded-For`, но только от прокси внутри Docker, поэтому подделать адрес заголовком нельзя.
