# Демо-семья для проверки интерфейса

Вместо ручной регистрации по почте (код из письма, приглашения, расписания) один раз создаём готовую семью и входим под нужным участником одной командой. Работает только на локальной БД: скрипт отказывается запускаться на чужом хосте.

## Участники

| Имя | Роль | Email | Особенности |
|---|---|---|---|
| Лена | мама, владелец | lena@demo.test | видит «Уроки и тренировки детей», может выдавать задания |
| Игорь | папа | igor@demo.test | родитель, не владелец |
| Миша | ребёнок, 12 лет | misha@demo.test | **день рождения сегодня**, уроки Пн–Пт, тренировки Вт/Чт/Сб, свои и чужие задания |
| Аня | ребёнок, 8 лет | anya@demo.test | уроки Пн–Пт, тренировки Ср/Вс |

Задания: ежедневные («Вынести мусор» 20:30, «Покормить кота» 08:00), недельное («Собрать портфель»), ежемесячное, разовое, просроченное («Сдать книги в библиотеку»), без срока («Купить хлеб и молоко»), часть выполнена. Даты считаются от сегодняшнего дня, поэтому демо всегда «живое».

## Порядок работы

1. **Окружение.** БД и Mailpit: `npm run dev:infra`. Сервер и фронтенд: `npm run dev` (адрес Vite в выводе, обычно http://localhost:5173; если порт занят, он берёт следующий). Проверка: `curl -s localhost:<порт>/api/health` возвращает `{"status":"ok"}`. Если уже запущено, ничего не перезапускай.
2. **Создать семью:** `npm run seed` из корня. Прежняя демо-семья удаляется и создаётся заново (остальные данные БД не трогаются), так что **повторный `seed` обнуляет все прежние входы**. Делай его один раз за сеанс или когда нужны свежие данные.
3. **Войти под участником:** `npm run seed -- --snippet Миша` печатает JavaScript. Выполни его в открытой странице приложения (инструмент браузера `javascript_exec`; страница должна быть на адресе приложения, иначе IndexedDB не тот). Код записывает вход в IndexedDB и переходит на `/my-day`. Семью он не пересоздаёт, только выдаёт свежую сессию, поэтому можно сколько угодно переключаться между участниками (`--snippet Лена`, `--snippet Аня`, …). Незнакомое имя даёт список допустимых.
4. **Мобильный вид:** `resize_window` с `preset: "mobile"` (375×812) и при необходимости `colorScheme` light или dark; после проверки верни `preset: "desktop"`. Пересоздавать семью ради смены темы не нужно.

## Другие режимы

- API-проверки (curl, скрипты): `npm run seed -- --existing --json` печатает `memberId` и токен каждого участника для заголовка `Authorization: Bearer <токен>`.
- Вход по почте, как у настоящего пользователя: на странице входа email из таблицы, код приходит в Mailpit (UI http://localhost:8025, API `http://localhost:8025/api/v1/search?query=to:lena@demo.test`).
- Сброс входа в браузере: в консоли `indexedDB.deleteDatabase('keyval-store')`, затем перезагрузка.
- Проверка плановых уведомлений: `npm run notify:tick -- 10:05 --reset` (день рождения Миши) и `-- 17:05 --reset` (уроки), но нужен включённый push на устройстве.

## Ловушки

- Во встроенной панели браузера нет работающих service worker и уведомлений: «Настройки → Уведомления» там покажут «запрещены». Настоящий push проверяй в обычном Chrome на собранной версии (`docker compose up --build`).
- Вход привязан к адресу сайта: сниппет на `localhost:5173` не залогинит `localhost:8080`.
- Сниппет содержит настоящий токен сессии: не вставляй его в коммиты, чаты и тикеты (в БД хранится только хэш, но сам токен даёт вход).
- Не запускай `seed` на боевой БД. Защита (`--force`) нужна только для осознанных случаев.
- В zsh не называй переменную цикла `path`: она связана с `PATH`, и команды перестанут находиться.
