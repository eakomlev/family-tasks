# Деплой на сервер

Прод это настоящая семья с живыми данными, поэтому деплой делаем только по прямой просьбе пользователя. Сервер подтягивает код из GitHub (`git pull --ff-only` внутри `update.sh`), поэтому **сначала всё нужное должно быть запушено в `main`** (пушим только по просьбе пользователя, см. CLAUDE.md). Локальные незапушенные коммиты на сервер не попадут.

## Параметры

В локальном `.env` (он в `.gitignore`) лежат `SERVER_IP`, `SERVER_USER`, `SERVER_PASSWORD`. Вход по паролю, `sshpass` на этой машине нет. Пароль не печатаем, не пишем в командную строку и не показываем в ответах: читаем только строки `SERVER_*` и отдаём пароль ssh через `SSH_ASKPASS`.

Проект на сервере лежит в **`/home/family-tasks`** (не в `~`).

## Шаги

1. Убедитесь, что нужное запушено: `git status -sb` и `git log origin/main -1`.
2. Создайте в scratchpad скрипт-подсказку пароля (один раз за сессию):

   ```bash
   S=<scratchpad>; printf '#!/bin/sh\nprintf "%%s" "$SERVER_PASSWORD"\n' > $S/askpass.sh && chmod 700 $S/askpass.sh
   ```

3. Общая обвязка для каждой команды на сервере (из корня проекта):

   ```bash
   set -a && . <(grep -E '^SERVER_' .env) && set +a
   SSH_ASKPASS=$S/askpass.sh SSH_ASKPASS_REQUIRE=force ssh -o StrictHostKeyChecking=accept-new -o PreferredAuthentications=password "$SERVER_USER@$SERVER_IP" '<команда>'
   ```

4. Проверка перед обновлением: `cd /home/family-tasks && git status -sb && git log --oneline -1 && docker compose ps` (нет ли локальных правок на сервере, что запущено).
5. Обновление: `cd /home/family-tasks && ./update.sh` (в Bash-инструменте поставьте `timeout` до 600000: сборка Docker занимает минуты). Скрипт сам: `git pull --ff-only`, копия БД в `backups/`, `docker compose up -d --build`, проверка здоровья изнутри и по HTTPS, `docker image prune`.
6. Прочитайте конец вывода: «Сервер и база работают», «Сайт отвечает по HTTPS», «Версия: <коммит>». Версия должна совпасть с `git rev-parse --short origin/main`.
7. Сообщите пользователю результат. Если скрипт предупредил про изменившийся `.env.example` или новые миграции, перескажите это (миграции применяются сами при старте сервера, откат кода схему не откатывает).

## Если что-то пошло не так

- `update.sh` при неудаче сам показывает лог сервера и команду отката (`git checkout <прежний коммит>`). Откат кода миграции не откатывает; копия БД лежит в `/home/family-tasks/backups/`.
- Не удаётся зайти: проверьте `SERVER_*` в `.env` и что сервер доступен; не перебирайте пароли и не меняйте настройки ssh.
- Не выполняйте на сервере ничего, кроме `update.sh` и чтения состояния (`git`, `docker compose ps/logs`), без отдельной просьбы: особенно `docker compose down -v` (стирает базу и сертификаты), правки `.env`, `git reset`.

## Замечено при первом деплое

- На сервере запущен контейнер `mailpit` с открытым портом 8025 (в `docker compose ps` он есть). В проде его включать не нужно (CLAUDE.md: «Почта обязательна»); проверьте `COMPOSE_PROFILES` в серверном `.env`.
