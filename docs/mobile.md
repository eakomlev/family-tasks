# Мобильное приложение (`mobile/`)

> Expo-приложение: команды, навигация, сборки APK и iOS, чат, тема, «Поделиться», уведомления. Общая карта проекта и правила: [CLAUDE.md](../CLAUDE.md). Ссылки «раздел ниже» в тексте относятся к этому файлу или к соседним файлам в `docs/`.


План и решения: `docs/mobile-app-plan.md` (фазы 0–9, статус фазы 2 в разделе «Состояние фазы 2»). Expo SDK 58, Expo Router (`src/app`), TypeScript, `styled-components/native`, RTK Query. **Общей кодовой базы с `web/` нет:** подходящие модули скопированы (`api/`, `store/`, `realtime/`, `lib/`, `identity/`, `profile/`) и дальше живут отдельно; исправление логики, нужное обоим, вносите в оба места, пока жива веб-версия. Пока в приложении: вход по email и коду, создание семьи и присоединение по приглашению, «Мой день» (настроение, уроки, тренировки, сводка по детям), разделы «Задания», «Семья», монеты и цели, профиль и тема, «Чат» с фото и файлами, расписания, «Что ты хочешь сообщить!», семейный календарь (уведомлений ещё нет) (приветствие, прогресс, задания на сегодня), табы с заглушками. Правила проекта те же (русский язык, комментарии на русском, защита от двойного нажатия, цвета из темы).

- **Команды:** `cd mobile && npx expo start`; `npm run typecheck`; `npm test` (Vitest в Node, около секунды; из корня `npm run test:mobile`); `npx expo-doctor`; сборка-проверка `npx expo export --platform android`. Версии пакетов ставьте только `npx expo install`; для Expo писать код по актуальной документации (`mobile/AGENTS.md`), SDK новее обычных знаний. CI: задание `mobile` (типы и тесты).
- **Адрес сервера:** `EXPO_PUBLIC_API_URL` (`lib/config.ts`; по умолчанию `http://localhost:8080`, на телефоне нужен адрес компьютера в сети). По нему API (`/api`), WebSocket и ссылки приглашений.
- **Хранение:** токен сессии в SecureStore (`identity/`), кэш данных и настройки в MMKV через `lib/kv.ts` (`getKv()`, синхронный интерфейс `KeyValueStore`; в Node и тестах хранилище в памяти, подмена `setKv`). MMKV и push не работают в Expo Go: нужна development-сборка.
- **Тесты** (`mobile/tests/`, Vitest, среда Node): только логика и хранилище данных; `react-native` и NetInfo подменены (`tests/stubs`, алиасы в `vitest.config.ts`), часовой пояс `Europe/Moscow`, адрес сервера в тестах `https://family.test`. Экраны проверяйте на устройстве; быстрый просмотр вёрстки в браузере: `npm run web:preview` (порт 8090, конфигурация `mobile-web` в `.claude/launch.json`; на вебе нет SecureStore и MMKV, поэтому вход не сохранится, на телефоне и в эмуляторе не проверялось).
- **Сборка APK** (`.github/workflows/mobile-apk.yml`): на каждый пуш в `main` с изменениями в `mobile/` (и вручную) Actions собирает подписанный APK (`expo prebuild` + `gradlew assembleRelease`, arm64 и armeabi-v7a) и пересоздаёт релиз `mobile-latest`; ссылка `https://github.com/<репозиторий>/releases/download/mobile-latest/moya-semya.apk` постоянная. Нужны секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` и переменная репозитория `MOBILE_API_URL` (адрес сервера вшивается в сборку); создание ключа и секретов описано в `mobile/README.md`. Подпись и `versionCode` (номер запуска) подключает плагин `plugins/withReleaseSigning.js`; он падает с понятной ошибкой, если шаблон `build.gradle` в новом SDK Expo изменился. Ключ подписи нельзя терять: без него новые сборки не обновят установленное приложение. Папка `android/` в `.gitignore`; `expo prebuild` перезаписывает скрипты `android` и `ios` в `package.json`, после локального запуска верните `expo start --android` и `expo start --ios`. Локально сборка проверена на Windows (JDK 17, Android SDK 37, Gradle 9.4.1): APK около 39 МБ (arm64), подпись своим ключом и `versionCode` из окружения подтверждены `apksigner` и `aapt2`; на Linux в Actions workflow ещё не запускался. Ловушки Windows: лимит пути 260 знаков роняет ninja (`mkdir(...): No such file or directory`), у ninja 1.10 из Android SDK длинные пути не поддерживаются даже при `LongPathsEnabled`, поэтому локально собирайте скриптом `mobile/scripts/build-apk-windows.ps1` (короткая папка `E:m` и `ANDROID_CXX_STAGING=E:`, плагин передаёт её как `buildStagingDirectory`); в Groovy запись `versionCode (x).toInteger()` разбирается как вызов функции, пишите `versionCode Integer.parseInt(x)`.
- **Значки приложения** (`mobile/assets/images/*.png`) генерируются из `web/public/icon.svg` скриптом `node scripts/generate-icons.cjs` (в `mobile/`, берёт `sharp` из `media/node_modules`): `icon.png` для iOS, фон, передний план и одноцветный значок для адаптивных значков Android (рисунок в центральных ~60%), `splash-icon.png`, `favicon.png`. Меняете рисунок: правьте SVG в `web/public` и `HOUSE`/`CHECK` в скрипте и запускайте его заново.
- **Структура навигации** (`src/app/(app)`): внутри `(app)` лежит группа `(tabs)` с четырьмя главными разделами (`index` «Мой день», `tasks`, `chat`, `family`) и панелью табов в `(tabs)/_layout.tsx`, а рядом обычные экраны поверх них: `profile`, `coins`, `goals`, `calendar`, `lesson-report` (у каждой папки свой `_layout` со Stack). **Не прячьте разделы через `Tabs.Screen options={{ href: null }}`**: в этой версии Expo Router скрытая вкладка недоступна и переход на неё молча перенаправляет на первую вкладку («Мой день»; так «не открывался» профиль). Верхний правый угол (баланс монет ребёнка и значок профиля, оба только на «Моём дне») рисует `TopRight` в `(app)/_layout.tsx` поверх экранов, поэтому заголовки страниц (`PageTitle`) оставляют справа `TOP_RIGHT_RESERVE`, а `Screen` сверху только небольшой отступ. Новые экраны делайте в `src/features/<раздел>/…Screen.tsx`, а в `app/` оставляйте тонкий файл маршрута.
- **Навигация «как в мобильных приложениях»:** в `(tabs)` лежат только корни четырёх разделов (`index`, `tasks/index`, `chat/index`, `family/index`) с панелью табов. Всё остальное (задание и его форма, переписка, участник семьи, приглашение, удаление семьи, цели, профиль, календарь…) лежит в `(app)` в общем Stack поверх табов, панель там скрыта (`tabBarVisible` в `lib/tabBar.ts` истинно только на четырёх корнях). Поэтому «назад» (стрелка слева сверху `BackLink`, жест, кнопка Android) возвращает именно на экран, откуда пришли (например, из задания, открытого в календаре, в календарь), а не на «Мой день». Не кладите экраны-вложения внутрь `(tabs)/<раздел>/`: открытие их из другого раздела переключает вкладку. Возврат кодом: `goBack(router, запасной адрес)` из `lib/navigation.ts` после сохранения, `router.dismissTo(адрес)` после удаления (страница удалённого объекта остаётся в стеке и её надо пропустить). URL-ы не менялись.
- **Меню «три точки»** раскрывается рядом со значком, как настоящее всплывающее меню (`components/PopupMenu`: `MenuButton` с пунктами `MenuAction`, у пункта-переключателя `checked`); панель снизу (`ActionSheet`) остаётся для долгого нажатия (строка чата, задание). Новое меню с тремя точками делайте через `MenuButton`. На «Заданиях» вкладок «Предстоящие/Выполненные» нет: список предстоящих, а выполненные за месяц появляются под ним по пункту «Показать завершённые» в меню рядом с «＋» (состояние общее с экраном, `features/tasks/viewState.ts: useTasksView`, хранится на устройстве); долгое нажатие на своё задание (где человек автор) открывает «Изменить» и «Удалить» (`TaskItem`, работает и на «Моём дне»).
- **Информация о чате** (приложение: `features/chat/ChatInfoScreen`, маршрут `/chat/[chat]/info`; веб: `pages/ChatInfo`, маршрут `/chat/:chat/info`, нажатие на имя в шапке переписки, подгрузка списков `lib/useCursorList.ts`, тест `web/tests/components/ChatInfo.test.tsx`): нажатие на имя в шапке переписки открывает страницу, как в Телеграме: собеседник (фото, роль, дата рождения, «Открыть профиль»), общий чат или событие, переключатель уведомлений, «Поиск сообщений» и вкладки «Медиа» (все фото, `listChatMedia`) и «Ссылки» (`listChatLinks`). Пункта «Медиа файлы» в меню чата больше нет (страницы `/chat/:chat/media` в вебе тоже нет). Сервер: `GET /api/chats/:chat/search?q=&before=` (подстрока без учёта регистра, без сообщений только с вложениями, 30 на страницу, символы `%` и `_` ищутся как текст) и `GET /api/chats/:chat/links?before=` (ссылки http(s) из текста, страница считается по сообщениям, в ответе `lastMessageId` для следующей страницы); доступ как к самому чату. Результаты поиска пока не ведут к сообщению в переписке (прыжка к старому сообщению нет). Подгрузку страниц по курсору делает `useCursorList`.
- **Сборка для iPhone и TestFlight** (`.github/workflows/mobile-ios.yml`, только вручную: минуты macOS дорогие; подробно в `mobile/README.md`): `expo prebuild --platform ios` и `pod install` на `macos-15`, номер сборки (`CFBundleVersion`) равен номеру запуска, `xcodebuild archive` и `-exportArchive` с `destination upload` и автоматической подписью по ключу App Store Connect API (`APPLE_TEAM_ID`, `APPSTORE_KEY_ID`, `APPSTORE_ISSUER_ID`, `APPSTORE_KEY_P8_BASE64`; сертификаты хранить не нужно). Нужны аккаунт Apple Developer и запись приложения с bundle id `ru.familytasks.mobile`. В `app.json` для iPhone: `usesNonExemptEncryption: false`, плагин `expo-image-picker` с описаниями доступа к фото и камере (без него приложение закрывается при выборе фото), `expo-notifications` в режиме `production`, расширение «Поделиться» на iOS выключено (нужна отдельная подпись и группа приложений). Prebuild iOS на Windows не работает. Push на iPhone: `usePush.ts` регистрирует токен APNs с `platform: 'ios'`.
- **Листание табов:** `(tabs)/_layout.tsx` построен на `TopTabs` из `expo-router/js-top-tabs` (`react-native-pager-view` и `react-native-tab-view`, нативный модуль: нужна новая сборка APK) с `tabBarPosition="bottom"` и своей плавающей панелью `FloatingTabBar`. Четыре главных раздела листаются пальцем влево и вправо, нажатие на таб тоже плавно прокручивает. Значки, подписи и бейджи («Задачи», «Чат») рисует сама панель; новый таб добавляйте в `TABS` и папкой в `(tabs)`.
- **Мгновенная отправка в чате:** сообщение появляется в ленте сразу и уходит в фоне (`features/chat/pending.ts`: хранилище в памяти приложения вне экрана, поэтому отправка идёт и после выхода из чата; статусы `sending` (часы в пузыре), `failed` (красная иконка слева от пузыря, нажатие открывает меню «Отправить ещё раз» и «Удалить»), `done` (экран забирает ушедшее в ленту одним шагом). Вложения грузятся до нажатия «Отправить», поэтому повтор не загружает их заново. Если ответ потерялся при удавшейся отправке, повтор даст дубль (идемпотентности на сервере нет). Звук отправки: `lib/sound.ts` (`expo-audio`, `assets/sounds/send.wav`, генерируется `node scripts/generate-sound.cjs`; не перебивает чужую музыку, в беззвучном режиме молчит). Новый нативный модуль: нужна новая сборка APK.
- **Чат в стиле Телеграма** (веб и приложение одинаково): шапка и панель ввода парят над лентой без фона, под ними лента затемняется градиентом (`expo-linear-gradient`, цвета через `lib/colorAlpha.ts: withAlpha`: в градиенте нужен тот же цвет с нулевой прозрачностью, не слово transparent), кнопки и поле это полупрозрачное «стекло» (заливка с прозрачностью и тонкая рамка; настоящего размытия в приложении нет, `expo-blur` не подключали). Устройство экрана (`ChatRoomScreen`): внутри `KeyboardAvoidingView` лежит `View flex:1`, в нём лента, парящая шапка (`position: absolute`, высота в `topHeight` по `onLayout`) и `Composer` (абсолютно внизу, высота через `onHeight` в `bottomHeight`); лента перевёрнута, поэтому её `paddingTop` стоит **внизу** (под панелью), а `paddingBottom` вверху (под шапкой). Аватар автора слева от чужих сообщений в групповом чате (`senderAvatar`, как в вебе: у последнего подряд от одного автора, у предыдущих пустое место); время всегда полосой внизу пузыря, у фото тоже (плашки поверх снимка нет). Веб-просмотр приложения (`npm run web:preview`) чинят заглушки в `metro.config.js` (`react-native-pager-view`, `expo-secure-store` через localStorage), а `ShareReceiver` и `NotificationsBridge` на вебе не рендерятся; адрес сервера для него `EXPO_PUBLIC_API_URL` на прокси с CORS (сервер заголовков CORS не отдаёт).
- **Поле ввода чата** (`features/chat/Composer.tsx`) растёт по высоте вместе с текстом, как в Telegram: до пяти строк (`MAX_LINES`, высота строки масштабируется шрифтом), дальше внутри появляется прокрутка. Ловушка: `flex: 1` на многострочном `TextInput` внутри колонки схлопывал его до `min-height`, и поле не росло. Клавиатура не должна перекрывать поле: в обычной переписке это `KeyboardAvoidingView`, на странице события (чат внутри пейджера) отступ снизу считается по `Keyboard`-событию (`Dimensions.get('screen').height - screenY`); проверять на эмуляторе, открыв клавиатуру в обоих местах.
- **Эмодзи в чате:** кнопка-смайл внутри поля ввода открывает свою панель вместо клавиатуры (`features/chat/EmojiPanel.tsx`, наборы и логика в `emoji.ts`: 7 категорий и «Недавние» в MMKV, вставка по курсору `insertAt`, стирание целого эмодзи `deleteBefore` с учётом ZWJ, оттенков кожи и вариантов начертания). Нативных модулей нет. Полного набора Unicode нет, список ограничен: новые добавляйте в `EMOJI_CATEGORIES`.
- **Тема и панель табов:** светлая палитра спокойная (фон `#f5f6fb`, белые карточки, один акцент индиго), панель табов белая с мягким индиго у активного; у тёмной активный таб лаймовый (токены `tabbarActiveBg`/`tabbarActiveText`). Подложка активного таба одна и плывёт за страницей (`position` из `TopTabs`, `near` меняется на полпути между табами), поэтому подсветка не отстаёт при свайпе, а по нажатию загорается сразу; `lazyPreloadDistance: 1` рендерит соседние страницы заранее. Значки системной строки задаёт `StatusBar` в `ThemeProvider` по теме приложения, а явный выбор темы передаётся системе через `Appearance.setColorScheme`. **Подложка панели табов полупрозрачная с размытием** (28 октября 2026, веб и приложение): веб `--tabbar-bg` rgb с прозрачностью 0,55 и `backdrop-filter: blur(10px)` (`--tabbar-bg-solid` для каймы счётчика), приложение `BlurView` из `expo-blur` (нативный модуль, нужна новая сборка Android и iPhone; `experimentalBlurMethod="dimezisBlurView"` для Android, на устройстве не проверялось) под полупрозрачным фоном панели в `(tabs)/_layout.tsx` (тот же вид у `components/PillTabs`: переключатель вида календаря и «Событие | Чат»; в вебе у календаря переключатель День/Неделя/Месяц стоит на тех же токенах `--tabbar-*` со скользящей подсветкой, «Сегодня» отдельная таблетка над ним), тень Android отключена.
- **Размер шрифта** (профиль → «Оформление», `features/profile/ThemeScreen`): множитель 0,8–1,5 с шагом 0,05 (`theme/fontScale.ts`, хранится в MMKV под ключом `fontScale`, стандартный размер ничего не хранит). Он лежит в теме (`theme.fontScale`), поэтому `Text` (`$size`), `Input`, поле чата и подписи табов масштабируются сами, остальным ничего делать не нужно. Новый текст с размером в пикселях пишите через `Text` с `$size` или умножайте на `theme.fontScale` (так же фиксированные `lineHeight`). Ползунок свой (`components/Slider`, `PanResponder`, без нативных модулей).
- **«Поделиться» из других приложений** (`expo-sharing`, плагин в `app.json`: Android принимает `text/plain`, `image/*` и любые файлы, один и несколько; iOS через Share Extension, `ios.enabled`, группа приложения по умолчанию `group.ru.familytasks.mobile`, **на iPhone не проверялось**, нужна новая нативная сборка и зарегистрированная группа). Первый запуск по «Поделиться» `src/app/+native-intent.ts` ведёт на `/share`, уже открытое приложение и вход после передачи подхватывает `ShareReceiver` (в `(app)/_layout.tsx`, `useIncomingShare`). Экран `/share` (`features/share/ShareScreen`): что получили и список всех чатов (в том числе архивных и чатов событий с сообщениями); выбор открывает переписку, а полученное ложится в поле ввода (`lib/incomingShare.ts`: `classifyShared` раскладывает на текст, картинки и файлы, `setPendingShare`/`takePendingShare`; `Composer` берёт `incoming` один раз: текст в поле, картинки как фото, остальное файлами с обычными проверками размера и запрещённых видов), человек дописывает подпись и жмёт «Отправить». Ловушки: у полученной картинки нет размеров, их узнаёт `Image.getSize`; проверять на эмуляторе нужно с настоящим `content://` и разрешением на чтение (`am start … -d <uri> --grant-read-uri-permission`), голый `file://` и чужой `content://` без разрешения дают «Ошибка» на вложении; загрузка фото работает только при запущенном сервисе `media` (`npm run dev:media`).
- **Нажатие на уведомление** (`features/notifications/`): сервер и планировщик кладут в `data.url` адрес «как в вебе» (`/tasks/<id>?date=`, `/chat/<чат>`, `/coins`, `/goals/<id>`, `/family/<id>`, `/profile`, `/profile/notifications`, `/my-day`), `route.ts` проверяет его (только внутренний адрес), `deepLink.ts: targetForPath` переводит в маршрут приложения: `/my-day` → корень («Мой день»), `/chat/event-<id>` → страница события со вкладкой «Чат», незнакомый раздел не открывается; корни табов открываются через `router.navigate`, остальное `router.push` поверх. Новый адрес в уведомлении: проверьте, что экран есть в приложении, и добавьте строку в `tests/unit/notificationDeepLink.test.ts`.
