# Миграция данных интерфейса на Redux Toolkit (RTK Query)

Статус: **миграция закончена** (фазы 0-6). Статус каждой фазы обновляйте в таблице внизу.

## Зачем

- Страница открывается с уже сохранёнными данными (кэш в `localStorage`), а свежие приходят следом: нет пустых экранов и «Загрузка…».
- События сокета только инвалидируют кэш: данные дальше запрашиваются сами, там, где они нужны.
- Меньше запросов: одинаковые запросы объединяются, а лишние перезапросы на каждом переходе уходят. Исходная точка (журналы nginx за 12 минут, 12 октября 2026): один iPhone делал около 100 запросов в минуту; открытие «Моего дня» у родителя даёт до 13 запросов (`me`, `tasks` дважды, `tasks/pending`, `schedule` и `trainings` на каждого ребёнка); при быстром переключении табов упирались в общий лимит.
- Сейчас у каждого экрана свой `useEffect` с `useState`, счётчик `version` и подписка `useLive`: 28 мест чтения и 20 подписок на события.

## Решения

1. **Серверные данные: RTK Query** (`createApi`): кэш, дедупликация, теги инвалидации, фоновое обновление. Клиентское состояние (вход, интерфейс) при необходимости в обычных `createSlice`.
2. **События сокета → `api.util.invalidateTags`** (см. `web/src/store/invalidate.ts`). Инвалидации склеиваются на 200 мс, чтобы `resync` не давал всплеска запросов.
   | Событие | Теги |
   |---|---|
   | `tasks` | `Tasks`, `Pending`, `Done` |
   | `members` | `Me`, `Coins`, `Earned` |
   | `schedule` / `trainings` | `Schedule` / `Trainings` (и `memberId`, когда он есть) |
   | `goals` | `Goals` |
   | `chat` | `Chats`, `Messages` |
   | `resync` | все теги |
3. **Хранение собственным слоем, не `redux-persist`** (`web/src/store/persist.ts`, около 150 строк): нужно читать данные синхронно при старте, ключи по пользователю, версия схемы, срок жизни 7 дней, бюджет размера, очистка при выходе. В хранилище попадает только `api`-срез (`queries` и `provided` со статусом «выполнен»), возвращается в RTK Query через `extractRehydrationInfo`.
4. **Хранилище `localStorage`** (около 5 МБ). Основной объём это data URL аватарок и картинок целей (до 70 КБ). При превышении бюджета или ошибке квоты отбрасываем самые старые записи, при ошибке записи работаем без кэша.
5. **Токен остаётся в IndexedDB.** Базовый запрос читает его лениво (`store/session.ts`, значение выставляет `SessionSync` при загрузке входа). Копию данных входа в `localStorage` не делаем: чтение IndexedDB занимает единицы миллисекунд, а ждать приходилось бы сеть; данные для оболочки берутся из кэша RTK Query.
6. **После загрузки из хранилища все записи считаются устаревшими:** один раз `invalidateTags` по всем тегам. Экран рисуется из кэша, активные подписки обновляются в фоне.
7. **Безопасность на общем устройстве.** Кэш лежит по ключу пользователя; указатель на текущего пользователя в `localStorage`. При выходе, ответе 401 или смене пользователя кэш стирается (в памяти и в хранилище). Хранилище из-за смены пользователя не используется ни при каких условиях.
8. **Офлайн-очереди записи нет** (отметить задание без сети и отправить позже). Это отдельная большая задача.

### Что входит в фазу 0 (сделано)

- Зависимости `@reduxjs/toolkit`, `react-redux`.
- `web/src/store/`: `index.ts` (`makeStore`, `store`), `api.ts` (`api` с типами тегов и базовым запросом поверх `request()`: сохраняет `ApiError` и повтор на 429), `session.ts` (токен и пользователь для запросов), `persist.ts` (загрузка и сохранение), `invalidate.ts` (события сокета в теги), `hooks.ts` (типизированные хуки), `SessionSync` (связь входа и кэша), `RealtimeBridge` (события сокета в инвалидацию).
- `Provider` в `App`; мост и синхронизация сессии подключены, `useLive` работает параллельно и пока ничего не заменено.
- Тесты: круг «запрос → сохранение → новая страница → данные на первом кадре без запроса», срок жизни, версия схемы, смена пользователя, очистка при выходе, ошибка квоты, склейка инвалидаций.

### Что входит в фазу 1 (сделано)

- `getMe` — первый endpoint (`store/profile.ts`, тег `Me`); `ProfileProvider` стал тонкой обёрткой над `useGetMeQuery()`, контракт `useProfile()` (`data`, `failed`, `refresh`) не менялся, остальные 21 место использования не трогали.
- Профиль виден на первом кадре после чтения входа (из `localStorage`), свежий приходит следом. Данные моложе 30 секунд повторно не запрашиваются.
- Обновление: сигнал `members` (мост инвалидирует `Me`), возврат на вкладку (`setupListeners`), `refresh()`. На каждом переходе профиль больше не перезапрашивается.
- 401 по профилю по-прежнему выходит из аккаунта; обрыв сети вход не трогает. Запрос без прочитанного входа не уходит и не считается 401 (`no_session`).
- Живая проверка (демо-семья, 6 переходов между табами): запросов `/api/me` было 0 (раньше по одному на переход). Остались дубли других запросов, их уберут фазы 2 и 3: на «Моём дне» `tasks` вызывается трижды, `tasks/pending` трижды, `schedule` и `trainings` по два раза на ребёнка.

### Что входит в фазу 2 (сделано)

- `store/tasks.ts`: 4 чтения (`listTasks`, `listDoneTasks`, `listPendingTasks`, `getTask`) и 6 мутаций (создать, изменить, удалить, отметить, снять отметку, подтвердить). Запросы вызывают готовые функции `@/api` через `fromApi` (одна логика запросов, тесты по-прежнему подменяют `@/api`); ошибка превращается в простой объект для Redux и обратно в `ApiError` через `toApiError` на экранах.
- Мутации сбрасывают теги `Tasks`, `Pending`, `Done`, `Me`, `Coins`, `Earned`: списки, блок проверки, значок на табе и баланс обновляются сами, `onDone` и счётчики `version` убраны.
- Переехали экраны: `/tasks` (у каждой вкладки свой запрос, вторая не грузится, пока не открыта), «Задания на сегодня», детские карточки у родителя, блок «Ждут подтверждения» (`PendingReview`, `useReview`), просмотр и форма задания, значок на табе «Задачи» (`TaskBadgeProvider` теперь берёт данные из кэша без своих запросов).
- Просмотр задания: после отметки результат показывается сразу (локальная поправка поверх кэша, пока не придут свежие данные); поздравление «родитель подтвердил, пока вы на странице» срабатывает только по данным, полученным с сервера за эту сессию, а не по сохранённым с прошлого раза.
- Кэш на устройстве хранится только для текущего пользователя: при сохранении записи других пользователей удаляются.
- Живая проверка (демо-семья, те же 6 переходов между табами, что в фазе 1): запросов `tasks` было 12 и `tasks/pending` 8, стало 1 и 0. `schedule` и `trainings` (по 8) уберёт фаза 3.
- Оптимистичное обновление для отметок не делали (список обновится после ответа сервера за десятки миллисекунд); вернёмся, если на медленной сети это будет заметно.

### Что входит в фазу 3 (сделано)

- Переехали: уроки и тренировки ребёнка на «Моём дне», карточки детей у родителя (по компоненту-обёртке на ребёнка, так как хуки нельзя вызывать в цикле), плашка «Сегодня заработано», баланс на странице ребёнка, редакторы расписаний и тренировок (серверное состояние теперь из кэша, черновик правок по-прежнему локальный).
- Живая проверка (демо-семья, те же 6 переходов): запросов к API всего 1 (в фазе 1 было 36, до миграции около 100). Редактор: открытие, правка, сохранение работают, показывается «Расписание сохранено».

### Что входит в фазу 4 (сделано)

- `store/goals.ts`: список и карточка цели, создание, изменение, удаление, оплата. Ответ оплаты сразу кладётся в кэш карточки (`updateQueryData`: «Куплено» и новый баланс на экране без ожидания), затем сбрасываются цели, профиль, монеты и «заработано».
- `store/coins.ts`: первая (свежая) страница истории монет. Старые страницы по-прежнему подгружает сам экран по мере прокрутки (`mergeNewest` сохраняет их при обновлении первой страницы): отдельный endpoint на каждую страницу курсора усложнил бы склейку без выигрыша. Экран получает первую страницу из кэша на первом кадре.
- `store/profile.ts`: мутации `updateProfile` и `setMood` с мгновенным показом (правится и «я», и запись в списке семьи; при ошибке откат), затем профиль запрашивается заново; `refresh()` в этих местах больше не нужен.
- Переехали: история монет (`/coins`, `/coins/:memberId`), «Мои цели», список целей у родителя, карточка цели (оплата, удаление), форма цели (заполняется данными цели один раз, правки пользователя не затираются), настроение на «Моём дне», изменение профиля и фото.
- Живая проверка (демо-семья, ребёнок): настроение выбирается, окно закрывается, смайлик на месте; открытие «Монет» сразу показывает цели; оплата цели даёт «Куплено» на экране, запросы после покупки: карточка и профиль.
- Остались без кэша (нужны только разово или после действия): Roblox-аватар (`getRobloxAvatar`), приглашения (`getInvite`, `checkInvite`, `renewInvite`), вход и регистрация.

Отправленное сообщение и ответ на реакцию сразу кладутся в кэш переписки (`updateQueryData`), «прочитано» и отправка сбрасывают список чатов (значок непрочитанного на табе и превью пересчитываются).
- Решение по развилке из плана: отдельный срез на `createEntityAdapter` для сообщений не понадобился. Первая (свежая) страница в кэше RTK Query, старые страницы по кнопке «Показать более ранние» подгружает и держит сам экран (как история монет), `mergeLatest` сохраняет их при обновлении первой. В `localStorage` попадает первая страница (до 50 сообщений) каждой открытой переписки.
- Теги с адресом: сигнал сокета `chat` сбрасывает список чатов и только переписку этого чата (`{ type: 'Messages', id: chat }`), события `schedule` и `trainings` тоже только расписание нужного ребёнка. Сигнал `resync` сбрасывает всё.
- `ChatsProvider` стал тонкой обёрткой над `useListChatsQuery` (контракт `useChats()` прежний, токен не нужен). `ChatRoom` разделён на оболочку с `key` по чату и `Conversation`: при переходе в другой чат состояние (подгруженные страницы, прокрутка, «прочитано») начинается с чистого листа.
- Сохранены правила из `CLAUDE.md`: отметка «прочитано» ставится один раз на последнее чужое сообщение (`markedRef`), своё сообщение не вызывает цикл событий, при возврате на вкладку отметка повторяется.

- В `LessonReport` отправка сообщения тоже через мутацию (список чатов обновляется).

- Экраны больше не подписываются на сокет: `useLive` остался только в `RealtimeBridge`, счётчиков `version` нет.

## Правила для следующих фаз

- Новые чтения данных пишем как endpoints в `api` (`injectEndpoints`), экран использует хук запроса; руками `useEffect` с `fetch` больше не добавляем.
- Каждому endpoint нужны `providesTags` и (для записи) `invalidatesTags` из списка тегов в `store/api.ts`.
- Данные, которые нельзя показывать устаревшими без пометки, помечаем в экране (например, баланс монет перед оплатой цели всё равно запрашивается заново).
- Не кладём в кэш секреты (коды из писем, токены).
- Новая форма данных у существующего endpoint: поднять `CACHE_VERSION` в `store/persist.ts`.
